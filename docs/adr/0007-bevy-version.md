# ADR-0007: Bevy 0.18.1 を採用し、feature を明示列挙する

- **状態**: 承認
- **日付**: 2026-08-07

## 背景

[ADR-0001](0001-engine-selection.md) で Bevy を選定したが、**版を決めていなかった**。
Bevy は破壊的変更の多いエンジンで、版が変われば API はまとまって変わる。
M2（描画）に入る前に確定させる。

Bevy は今回のプロジェクトで**最大の依存**（413 パッケージ）でもある。
選定を誤ると、ビルドが通らない・エコシステムの資料が合わない・
MSRV が合わない、といった形で全体が止まる。

## 選択肢

crates.io の実データ（2026-08-07 時点）。

| 版 | 公開日 | MSRV | ダウンロード数 |
|---|---|---|---:|
| 0.19.0 | 2026-06-19 | **1.95.0** | 154 576 |
| 0.18.1 | 2026-03-04 | 1.89.0 | **465 338** |
| 0.18.0 | 2026-01-13 | 1.89.0 | 275 437 |
| 0.17.3 | 2025-11-17 | 1.88.0 | 245 065 |

開発環境の rustc は **1.93.0**。

## 決定

**Bevy 0.18.1。**

### 0.19.0 を採らない理由

**ビルドできない。** MSRV が 1.95.0 で、手元の 1.93.0 では解決すらされない。

```text
Adding bevy v0.18.1 (available: v0.19.0, requires Rust 1.95.0)
```

Rust を上げれば使えるが、公開から 7 週間しか経っておらず、
**エンジンとツールチェーンを同時に最新へ動かすのは M2 の入口でやることではない**。
描画が動かないとき、原因がこちらのコードなのか Bevy なのかツールチェーンなのかを
切り分けられなくなる。

### 0.17.3 を採らない理由

より枯れている（パッチ 3 回）が、公開から 9 か月。ダウンロード数でも 0.18 系に
抜かれており、**エコシステムの重心はすでに 0.18 にある**。今から 9 か月前の版に
乗る理由が無い。

### 0.18.1 を採る理由

1. **ビルドできる。** MSRV 1.89 ≤ 1.93。実際に検証済み（後述）
2. **エコシステムの重心。** 0.18.0 + 0.18.1 で 74 万ダウンロードと、単一系列で最多
3. **パッチが 1 回出ている。** 0.18.0 の初期不具合は踏まずに済む
4. 公開から 5 か月。資料と第三者クレートが揃っている

### 検証したこと

**版を決める前に、実際にコンパイルが通ることを確かめた。**
ビルドできない版を選ぶのは最悪の失敗であり、机上で決めない。

```text
Locking 413 packages to latest Rust 1.93.0 compatible versions
Finished `dev` profile in 35.42s
```

その過程で 1 つ踏んだ。`tonemapping_luts` は zstd バックエンドの明示を要求する。

```text
error: Choosing a zstd backend is required for zstd support.
       Please enable either the "zstd_rust" or the "zstd_c" feature.
```

**`zstd_rust`（純 Rust）を選んだ。** `zstd_c` は C ツールチェーンを要求し、
CI の Windows / Linux 双方でビルド環境の差異を持ち込む。

### feature は既定を切って明示列挙する

`default-features = false` としたうえで必要なものだけ有効にする。

| feature | 理由 |
|---|---|
| `bevy_render` / `bevy_core_pipeline` / `bevy_pbr` | 3D 描画と PBR マテリアル |
| `bevy_winit` / `bevy_window` / `x11` | ウィンドウ。`x11` は Linux CI 用 |
| `bevy_asset` | メッシュ・マテリアルのハンドル管理 |
| `bevy_ui` / `bevy_ui_render` / `bevy_text` / `default_font` | HUD |
| `tonemapping_luts` / `zstd_rust` | HDR トーンマッピング。空の見た目に直結する |
| `multi_threaded` | 並列スケジューラ |
| `std` | 標準ライブラリ |

**入れていないもの**: 音声、glTF、アニメーション、シーン、gizmo、開発ツール。
必要になった時点で足す。既定のまま全部入れると、使いもしない依存の
ビルド時間とバイナリサイズを払い続けることになる。

とくに音声を切っているのは意図的で、Linux CI が `libasound2-dev` を
要求しなくなり、CI のセットアップが 1 段簡単になる。

## 帰結

**受け入れるコスト**

- **MSRV が分岐する。** `render` / `input` / `ui` / `app` は 1.89 が要る。
  `core` / `fdm` / `world` / `sim` / `tilegen` は 1.85 のまま据え置く。
  純 Rust 側が古いツールチェーンで動く性質は維持する
- ビルド対象が 413 パッケージ増える。初回ビルドは数分かかる。
  ただし `cargo test -p flightsim-fdm` 等は従来どおり数秒で回る
  （Bevy 非依存の規約が効いている）
- Bevy の版上げは**独立した PR** として扱う。他の変更と混ぜない。
  API 変更がまとまって来るため、混ぜると原因の切り分けができなくなる
- Linux CI に winit のシステム依存（`libxkbcommon-dev` 等）が要る

**得られる保証**

- 描画層が動かないときに、ツールチェーンと Bevy 版を疑わなくてよい。
  切り分けの対象を自分たちのコードに絞れる
- feature を明示しているので、依存が増えた理由が manifest から追える

## 差し戻し条件

- Rust ツールチェーンを 1.95 以上へ上げる判断をしたとき、0.19 系を再評価する。
  **その際もエンジンだけを単独で上げること**
