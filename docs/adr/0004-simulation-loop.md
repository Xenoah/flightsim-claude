# ADR-0004: FDM を固定ステップ RK4 で回し、描画フレームレートから分離する

- **状態**: 承認
- **日付**: 2026-08-01

## 背景

剛体の 6DoF 運動方程式を可変 dt（＝描画フレーム時間）でそのまま積分すると、以下で破綻する。

- **失速時**: 迎角が急変する領域で係数が非線形。dt が伸びるとオーバーシュートして振動、最悪発散する。
- **接地時**: 脚のばねダンパは剛性が高い。dt が大きいと反発が増幅し、機体が跳ね飛ぶ。
- **再現性の喪失**: フレームレートが違うと結果が変わる。回帰テストが書けず、リプレイもマルチプレイの同期も成立しない。

3番目が特に重い。**FPS 依存の物理はテスト不能**であり、今回の開発体制（QA エージェントが回帰網を維持する）と根本的に噛み合わない。

## 決定

### 固定タイムステップ + アキュムレータ

```rust
const FIXED_DT: f64 = 1.0 / 120.0;   // 8.333 ms

accumulator += frame_time.min(MAX_FRAME_TIME);   // スパイラル防止のクランプ
while accumulator >= FIXED_DT {
    fdm.step(FIXED_DT);
    accumulator -= FIXED_DT;
}
let alpha = accumulator / FIXED_DT;               // 描画補間係数
```

- `FIXED_DT = 1/120 s`。60Hz では 2 ステップ、144Hz では 1〜2 ステップ。
- `MAX_FRAME_TIME = 0.25 s` でクランプ。これが無いと、重い1フレームが大量のステップを誘発し、それが更に次フレームを重くする **death spiral** に入る。

### 積分器は RK4

オイラー法は誤差 O(dt)、RK4 は O(dt⁴)。1ステップあたり導関数評価が4回になるが、剛体1機ぶんの計算量は些少であり、安定性の見返りが遥かに大きい。

### 内部サブステップ

接地・高剛性領域では `step()` 内部で更に分割する。呼び出し側の `FIXED_DT` は変えない（外部契約を安定させるため）。

```rust
fn step(&mut self, dt: f64) {
    let n = self.required_substeps();     // 状態に応じ 1..=8
    let h = dt / n as f64;
    for _ in 0..n { self.integrate_rk4(h); }
}
```

### 描画補間

描画は前ステップ状態と現ステップ状態を `alpha` で補間する。位置は線形補間、姿勢は quaternion の slerp。

**補間結果を物理状態に書き戻さない。** これをやると物理が描画に汚染され、再現性が消える。

## 不変条件（テストで検査する）

1. `fdm.step(dt)` は壁時計時間・フレームカウンタ・乱数を参照しない。同じ入力から常に同じ出力を返す。
2. 同一の初期状態と入力列に対し、実行環境によらずビット単位で同じ軌跡になる（`f64` 演算順序を固定する）。
3. 姿勢 quaternion は毎ステップ正規化される。ノルムの誤差が 1e-9 を超えない。
4. 無入力・無風・水平定常飛行の状態を 10 分ぶん積分しても、高度がトリム点から発散しない。

これらは `flightsim-fdm` の統合テストとして実装し、CI で常時検査する。

## 帰結

- FDM が壁時計から独立するため、**リプレイ機能とネットワーク同期の前提条件が最初から満たされる。** これらは要件にあるので、後付けにするより最初から分離しておく方が安い。
- ヘッドレスで N 倍速のシミュレーションが可能になる（10分の飛行を数秒でテストできる）。QA の回帰テストはこれを使う。
- 描画補間の実装を `render` 担当が忘れると、120Hz 物理を 60Hz で表示した際にわずかなジッタが出る。これは実装漏れとして検出しにくいので、**補間の有無を切り替えられるデバッグフラグを用意すること。**
