# ADR-0002: 世界座標を f64 ECEF とし、描画時に floating origin で f32 化する

- **状態**: 承認
- **日付**: 2026-08-01

## 背景

地球全体を飛べることが要件にある。地球の半径は約 6,378 km。

`f32` の仮数部は 24 bit なので、原点から 6.4e6 m 離れた点での表現可能な最小刻みは:

```
6.378e6 / 2^23 ≒ 0.76 m
```

つまり **`f32` で ECEF 座標を保持すると地表で約 76cm 単位の格子にしか位置を置けない。** 機体は毎フレーム別の格子点にスナップし、可視の振動として現れる。滑走路上の接地判定や計器の高度表示は成立しない。

`f64` の仮数部は 52 bit なので同じ距離で:

```
6.378e6 / 2^51 ≒ 2.8e-9 m
```

ナノメートル精度。十分すぎる。

## 決定

**3 層に分ける。**

### 1. 世界の正準座標 — `f64` ECEF

地心地球固定直交座標系。原点は地球重心、Z 軸が自転軸、X 軸が本初子午線と赤道の交点。

物理積分（位置・速度）は全てここで行う。ECEF は回転座標系だが、**現段階では慣性系として扱い、コリオリ力・遠心力を無視する**。

> 妥当性: 巡航速度 250 m/s、緯度 45° でのコリオリ加速度は 2Ωv sinφ ≒ 0.026 m/s²。重力の約 0.26%。当面は無視して差し支えないが、長距離巡航の航法誤差として効いてくるため **将来 `fdm` に補正項を足せる形で構造だけ空けておく**。無視していること自体をここに明記するのが本 ADR の役目。

### 2. ローカル接平面 — NED / ENU

姿勢角（ピッチ・ロール・ヨー）、風、航法計器はローカル水平面基準でないと意味を持たない。任意の測地座標点で ECEF ⇄ NED の基底を生成する。

**NED**（North-East-Down）を主として使う。航空分野の標準であり、正のピッチが機首上げ、正の Z が下向きになって空力の教科書と一致するため。

### 3. 描画座標 — `f32` + floating origin

カメラ近傍に `WorldOrigin`（`f64` ECEF のアンカー）を置き、描画対象は原点からの相対位置を `f32` で表現する。

```
render_pos_f32 = (object_ecef_f64 - origin_ecef_f64) as f32
```

カメラが一定距離（既定 4 km）動いたらアンカーを打ち直す。相対距離は高々数十 km なので `f32` でもミリメートル精度が保たれる。

## 規約

- **変換関数は `flightsim-core` にのみ置く。** 他クレートで `sin`/`cos` を使った座標変換を書くことを禁止する。丸め・特異点（極・子午線）の扱いが分岐すると、原因特定が極めて困難なズレを生むため。
- 公開 API では系を型で区別する（`Ecef`, `Geodetic`, `Ned`）。裸の `DVec3` を系の区別なく渡さない。
- ECEF → Geodetic は Bowring 法（反復2回）を用いる。閉形式より速く、地表付近で 1mm 以下の誤差に収まる。極近傍のみ別式に分岐する。

## 帰結

- `f64` 化により FDM のメモリ帯域と SIMD 効率は `f32` 比で劣化する。機体数が数百規模になった時点で再評価する（現時点では自機 + 少数の AI 機のみなので問題にならない）。
- Bevy の `Transform` は `f32` なので、**ECS のコンポーネントとして `f64` 位置を別途持ち、`Transform` は描画用の派生値として毎フレーム書き込む**。`Transform` を位置の正としないこと。
- floating origin の打ち直し時、`f32` 側の全オブジェクト位置を一括更新する必要がある。この処理はフレームスパイクになり得るため、`render` 担当はここをベンチ対象に含めること。
