## 次に薦めるタスク

### 第一候補: 雲と視程（Issue #11、`ready`）

M3 の「天候」で唯一残っている塊。**視程が下がると計器飛行の意味が出る**ので、
計器盤を作った直後のいまが繋がりが良いです。

分かっていること:

- 大気散乱は Bevy 0.18 の Bruneton モデル（`bevy_pbr` の `Atmosphere`）。
  **散乱は「散乱光 + 背景 × 透過率」を書く**ので、`ClearColor` を触ると
  空の色が変わる（夜が来なかった原因がこれだった）
- `SunLighting` / `TimeOfDay` が `flightsim-render/src/daylight.rs` にある。
  雲量を持たせるならここが素直
- 視程を FDM へ渡す必要は無い（空力に影響しない）。**描画だけの話**

注意:

- **雲量・雲底・雲頂の設定は決定論にすること。** 乱流と同じく、
  時刻と位置の関数にする（`flightsim-fdm/src/turbulence.rs` が手本）
- 昼夜で破綻しないこと。**夜の雲は自己発光しない**ので、環境光との
  兼ね合いを実機で見る必要がある

### 第二候補: 空港データ（OSM）

`ready` ですが、**着手前に決めることがあります。**

- 現状の滑走路は `Runway::synthetic()` ひとつだけの合成フィクスチャ
- OSM は ODbL。**取り込んだら `ATTRIBUTION.md` に帰属表示が要る**
  （`airport.rs` に「合成なので帰属不要」と明記してあるので、そこも直す）
- 複数滑走路になると `ActiveRunway`（app のリソース）の選び方が要る。
  「いちばん近い滑走路」で足りるはず

### 後回しを薦めるもの

## この回で確認した、効く作法

**3 件の欠陥を実機のスクリーンショットで見つけました。いずれも
純関数のテストは全部通っていました。**

1. **滑走路灯が夜に一つも見えなかった。** 明るさを材質の現在値から
   逆算していたため、一度 0 にすると二度と戻らなかった
2. **針が盤面の中心からずれていた。** 絶対配置で inset を省くと
   親の静的配置に依存する
3. **計器盤が左下の操作説明と重なっていた。** 幅を詰めても衝突した

→ **描画を変えたら必ず `--screenshot` で撮って目で見ること。**
純関数のテストは「値が正しいか」しか見ておらず、
「画面に出ているか」「重なっていないか」は一切見ていません。

もう一つ、**テストの期待値を 2 度直しました。** どちらも曲線ではなく
私の閾値が誤りで、**smoothstep の値を実装の出力ではなく定義から独立に
検算**して確定させています。実装の出力を写して期待値にすると、
実装が間違っていても永遠に通ります。

## 引き継ぐ時点で残っている懸念

**確認したことと推測を分けて書きます。**

### 確認済みの制限

- **コックピットに内装モデルが無い。** 計器盤と照明で「座っている感じ」は
  出ましたが、風防やダッシュボードの造形はありません。外形モデルは
  視界を塞ぐので隠したままです
- **ゲームパッドは実機で未検証**（Issue #2）。純関数とキーボード共存は
  テスト済みですが、実物を繋いだ確認は取れていません
- **実 DEM での夜間・高高度は未検証**（Issue #6）。合成飛行場でしか
  撮っていません
- **乱流の操縦感は未調整**（Issue #5）。数値と決定論は検証済みですが、
  「飛ばして気持ちいいか」は主観評価なので手を付けていません

### 推測（未検証）

- 計器の照明色（淡い橙）は**読みやすさを優先した判断**で、実機の
  計器照明は赤系です。暗順応の観点では赤が正しいので、
  夜間飛行を突き詰めるなら再考の余地があります
- 滑走路灯の大きさ（1.6 m 角）は実機の灯器より大きく、
  **遠方からの視認性を優先した**ものです。近づいたときに大きすぎないかは
  接地直前の画で確かめていません

## 作業の型（HANDOFF から再掲。特に効くもの）

- **`cargo test --workspace` は使わない。** メモリ枯渇（os error 1455）で
  落ちる。コードの問題ではない。CI と同じ 2 グループに分ける
- 変更したら `cargo fmt --all` → `cargo clippy ... -D warnings` →
  テスト 2 グループ → `cargo doc`（`RUSTDOCFLAGS="-D warnings"`）→
  `bash scripts/check-architecture.sh`。**`cargo doc` を忘れると CI で落ちる**
- doc コメントで `[m]` のような角括弧を単位に使わない
  （rustdoc が intra-doc link と解釈する）
- **画面に出す文字列は ASCII のみ。** 既定フォントに `°` の字形が無く、
  実機で豆腐が出た。`nothing_on_screen_uses_glyphs_the_default_font_lacks` と
  `the_landing_report_stays_ascii` が検査している
- **版を上げずに main へ push すると Release ワークフローが失敗する。**
  既存タグを別 SHA へ動かすのを拒否する安全動作で、バグではない。
  文書だけの変更でも `Cargo.toml` の版を上げるか、失敗を許容するか決めること
