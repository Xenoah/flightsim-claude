## 最初にやること

```bash
# 1. 地形タイルを焼く（実 DEM の入手は要らない）
cargo run -p flightsim-tilegen --example synthetic_dem -- data/synthetic.tif
cargo run -p flightsim-tilegen -- --input data/synthetic.tif --output data/tiles \
    --min-level 8 --max-level 12

# 2. 実際に飛ばして、いまどうなっているかを目で見る
cargo run -p flightsim-app --release -- --tiles data/tiles
cargo run -p flightsim-app --release -- --tiles data/tiles --approach 1.5 --turbulence moderate
```

**`data/tiles` と `data/synthetic.tif` は `.gitignore` 対象なので、
clone した直後は存在しない。** 焼かないと `[no terrain data]` になる。

## 次のタスク: 計器盤（`flightsim-ui`）

コックピット視点（`C` キー）が現状ほぼ空。外形モデルは視界を塞ぐので
隠してあり、内装モデルも無い。**計器が描かれていれば
「コックピットに座っている」感じになる。**

### 分かっていること

- `HudState` に必要な値は全部ある。`view_mode: &'static str` で
  コックピット視点かどうかも判定できる（`"COCKPIT"`）
- 針の滑らかさは `HudSmoothing` が既に面倒を見ている
- 置き場所の空きは**画面中央下**。左上=計器列、右上=着陸評価、
  左下=操作説明、右下=飛行記録、中央上=チュートリアルで埋まっている

### 踏みそうな穴

- **Bevy の UI で丸い針を描くのは面倒。** 横棒のテープ計器で済ませてもよいが、
  **判断理由を doc に書くこと**（「難しかったから」ではなく「こちらが読みやすい」なら）
- **`°` を画面に出さない。** 既定フォントに字形が無く豆腐になる。
  `deg` と綴り、既存の ASCII 検査に新しい文字列も足すこと
- 高度計の針が 1000 ft で 1 周すること、方位計が 359°→1° をまたぐとき
  逆回転しないこと、負の高度・NaN で壊れないこと。**これらは Bevy 非依存の
  純関数に切り出してテストする**

### 過去 2 回失敗している

このタスクをサブエージェントに投げて、**2 回ともセッション上限で落ちた。**
実装量が多い。**計器 1 つずつ刻んで、都度コミットすることを勧める。**

## このリポジトリで特に効いた作法

前任者が実際に不具合を見つけた手段。**推測ではなく、これで見つかった。**

1. **実データを通すまで「動く」と言わない。**
   glTF 経路は合成データのテストが全部緑のまま 3 件壊れていた
   （`reflect_auto_register` 欠落で panic、倍率が機首方位に依存、`jpeg` 欠落）。
   実際に Meshy から取った `.glb` を読んで初めて出た。

2. **色は目視ではなく画素を測る。**
   頂点色を sRGB のまま渡した不具合は、スクリーンショットを見ただけでは
   「そんなものか」で通ってしまった。平均画素値を測って確定した。

3. **安全網を足したら、意図的に壊して落ちることを確かめる。**
   薄明の修正・軸の漏れ・接地の測り方は、すべて旧実装を注入して
   検査が落ちることを確認してから採用した。**常に通る検査は何も保証しない。**

4. **文書のコマンドを実際に叩く。**
   README に書いてあった `cargo run -p flightsim-app` は**一度も動いていなかった**
   （`CARGO_MANIFEST_DIR` が `crates/flightsim-app` を指し、そこに `assets/` が無い）。
   検証時に `BEVY_ASSET_ROOT` を付けていたので気付けなかった。

## 引き継ぐ時点で残っている懸念

**確認したことと推測を区別して書く。**

### 確認済みの制限

- **ゲームパッドは実機で未検証。** 純関数とキーボード共存はテスト済みだが、
  実際のパッドを繋いだ確認は取れていない。符号（特にエレベータ）と
  感度は実機で見てほしい
- **夜間は地形が見えない。** 環境光の階調は直したが、夜そのものが暗いのは
  物理的に正しい（実際の市民薄明の照度は正午の 0.4% 程度）。
  **本当の答えは滑走路灯とコックピット照明で、それは未実装**
- ~~**自動操縦は滑走路へ戻る横方向誘導を持たない。**~~
  **2026-08-26 に解消**（`v0.6.0-alpha.6`）。最終進入で中心線を捕捉し、
  無風・左右 6 m/s の横風いずれでも滑走路内へ接地する受け入れテストがある。
  **これは回帰テスト用の幾何誘導であって、ILS でも認証された autoland でもない**

### 推測（未検証）

- 実 DEM（Copernicus）を積んだ状態での夜間・高高度の見え方は撮っていない。
  合成飛行場でしか確認していない
- 乱流の強度（light 1.5 / moderate 3.0 / severe 6.0 m/s）は
  航空気象の目安に合わせたが、**操縦して気持ちいいかは詰めていない**。
  上下成分を水平の 0.7 倍にしたのは体感の調整で、気象の実測値ではない

## 作業の型

- **`cargo test --workspace` は使わない。** メモリ枯渇（os error 1455）で落ちる。
  コードの問題ではない。CI と同じ 2 グループに分ける（CLAUDE.md 参照）
- 変更したら `cargo fmt --all` → `cargo clippy ... -D warnings` →
  テスト 2 グループ → `cargo doc`（`RUSTDOCFLAGS="-D warnings"`）→
  `bash scripts/check-architecture.sh`。**`cargo doc` を忘れると CI で落ちる**
- doc コメントで `[m]` のような角括弧を単位に使わない。
  rustdoc が intra-doc link と解釈して doc ジョブが落ちる
- 描画を変えたら `--screenshot` で撮って**必ず目で見る**
